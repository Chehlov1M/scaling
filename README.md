# Задание 1. Преимущества масштабирования

Активный master-сервер и пассивный репликационный slave-сервер

Этот подход (активный мастер + пассивный слэйв) фокусируется на отказоустойчивости и резервном копировании.

Основные преимущества:

- Защита от потери данных. Если мастер выходит из строя, пассивный слэйв уже содержит актуальную копию данных (с минимальным отставанием). Это позволяет быстро переключиться на резервный сервер без потери информации.
- Минимизация простоев. Переключение на резервный сервер (failover) занимает считанные секунды, что критично для бизнес-критичных систем.
- Разгрузка мастера для бэкапов. Бэкап можно делать не с основного сервера, а со слэва. Это снимает нагрузку с мастера, который отвечает за обработку транзакций.
- Возможность аварийного восстановления. Слэйв можно использовать как «точку отката» при случайном удалении данных или повреждении.
- Упрощённое администрирование. Конфигурация обычно проще, чем при множестве узлов, а логика репликации прозрачна.

Master-сервер и несколько slave-серверов

Этот подход расширяет преимущества первого, добавляя масштабирование нагрузки (read scaling).

Основные преимущества:

- Распределение нагрузки чтения. Запросы SELECT (чтение) можно направлять на слэвы, разгружая мастер, который занимается в основном INSERT, UPDATE, DELETE. Это позволяет обслуживать больше пользователей.
- Гибкость масштабирования. При росте нагрузки можно просто добавить ещё один слэйв, не меняя архитектуру мастера.
- Географическое распределение. Слэвы можно разместить в разных дата-центрах или регионах, снижая задержку для пользователей (low latency).
- Отказоустойчивость кластера. Наличие нескольких слэвов повышает надёжность: если один узел упадёт, остальные продолжат обслуживать запросы.
- Аналитика и отчёты. Тяжёлые аналитические запросы можно запускать на слэвах, не мешая операционным процессам на мастере.
- Резервирование данных в разных зонах. Снижается риск потери данных из-за сбоя в одной локации.
